# Scope Guard

## Workflow

1. Classify the requested action as allowed, risky, or blocked.
2. If blocked, refuse that part and offer a safe research alternative.
3. If risky, narrow the action to owned devices, supported flows, or SRD-authorized work.
4. Check whether the output could enable Activation Lock bypass or unauthorized access.

## Allowed

- evidence collection
- static inventory and notes
- supported-flow dynamic testing
- report drafting
- SRD-ready planning

## Blocked

- bypass instructions
- unlock automation
- credential theft or interception
- phishing or brute force
- activation service spoofing
- unauthorized access to data or accounts
